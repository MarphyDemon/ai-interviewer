## 一、项目架构

```
┌─────────────┐     ┌─────────────┐     ┌──────────────┐
│   前端 SPA   │────▶│   Nginx     │────▶│  FastAPI 后端 │
│  (Vue 3)    │     │  (反向代理)  │     │  (Python)    │
└─────────────┘     └─────────────┘     └──────┬───────┘
                                               │
                                               ▼
                                       ┌──────────────┐
                                       │ PostgreSQL   │
                                       └──────────────┘
```

| 服务         | 端口           | 技术栈                          | 说明       |
| ---------- | ------------ | ---------------------------- | -------- |
| **前端**     | 8080 (Nginx) | Vue 3 + Vite + Tailwind      | 静态 SPA   |
| **后端 API** | 8000 (内部)    | FastAPI + SQLModel + Uvicorn | REST API |
| **数据库**    | 5432 (内部)    | PostgreSQL 16                | 持久化数据    |
| **向量库**    | 文件存储         | ChromaDB                     | 知识文档向量   |

## 三、本地打包

### 3.1 构建前端

```bash
cd ai-interviewer
npm run build
```

产物目录：`dist/`

### 3.2 准备部署包

```bash
# 创建临时目录
rm -rf deploy-package
mkdir deploy-package

# 复制必要文件
cp -r dist deploy-package/
cp -r server deploy-package/
cp Dockerfile deploy-package/
cp docker-compose.prod.yml deploy-package/
cp -r deploy deploy-package/

# ✅ 不要复制：node_modules、.git、data、dist.bak 等
```

### 3.3 打包压缩

```bash
cd deploy-package
tar -czf ai-interviewer-deploy.tar.gz .
cd ..
```

压缩包内容：

```
ai-interviewer-deploy.tar.gz
├── dist/                    # 前端产物
├── server/                  # 后端代码（不含 .env，服务器上保留）
├── Dockerfile               # 镜像构建
├── docker-compose.prod.yml # 编排配置
└── deploy/
    └── nginx.conf           # Nginx 配置
```

## 四、服务器部署

### 4.1 前置条件

| 软件             | 版本要求   | 说明              |
| -------------- | ------ | --------------- |
| Docker         | ≥ 24.x | 容器运行时           |
| Docker Compose | ≥ 2.x  | 容器编排            |
| 系统内存           | ≥ 2GB  | PostgreSQL + 应用 |
| 磁盘空间           | ≥ 10GB | 数据存储            |

### 4.2 首次部署

```bash
# 目标目录
DEPLOY_DIR=/opt/ai-interviewer

# === 1. 创建目录并解压 ===
mkdir -p $DEPLOY_DIR && cd $DEPLOY_DIR
tar -xzf ai-interviewer-deploy.tar.gz

# === 2. 配置环境变量 ===
# 编辑 server/.env，填入必要配置
cat > server/.env << 'EOF'
DATABASE_URL=postgresql://postgres:your_password@postgres:5432/ai_interviewer
FERNET_KEY=your_fernet_key_here
EMBEDDING_API_KEY=your_embedding_api_key
EOF

# === 3. 启动服务 ===
docker compose -f docker-compose.prod.yml up -d
sleep 10

# === 4. 初始化数据库 ===
docker compose -f docker-compose.prod.yml exec backend python -c "import sys;sys.path.insert(0,'.');from server.database import init_db;init_db()"
```

### 4.3 迭代部署

```bash
cd /opt/ai-interviewer

# === 1. 备份旧版本 ===
cp -r dist "dist.bak.$(date +%Y%m%d_%H%M%S)" 2>/dev/null || true
cp -r server "server.bak.$(date +%Y%m%d_%H%M%S)" 2>/dev/null || true

# === 2. 解压新版本 ===
tar -xzf ai-interviewer-deploy.tar.gz

# === 3. 重建后端镜像 ===
docker compose -f docker-compose.prod.yml build --no-cache backend

# === 4. 重启服务 ===
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d
sleep 10

# === 5. 数据库迁移（仅模型变更时执行）===
docker compose -f docker-compose.prod.yml exec backend python -c "import sys;sys.path.insert(0,'.');from server.database import init_db;init_db()"
```

## 五、场景决策树

```
收到新版本 → 判断变更类型
    │
    ├── 仅前端（dist/ 有变更）
    │   └── 解压 → 重启 Nginx 容器即可
    │       docker compose -f docker-compose.prod.yml restart nginx
    │
    ├── 仅后端（server/ 有变更）
    │   └── 解压 → 重建后端镜像 → 重启
    │       docker compose -f docker-compose.prod.yml build --no-cache backend
    │       docker compose -f docker-compose.prod.yml up -d
    │
    ├── 数据库模型变更
    │   └── 解压 → 重建镜像 → 重启 → 执行迁移
    │       （见 4.3 步骤 6）
    │
    └── 全栈变更
        └── 解压 → 重建镜像 → 重启 → 执行迁移
```

## 六、数据库迁移记录

### v3.4 迁移内容（2026-09-18）

| 变更类型 | 对象                        | 说明                                    |
| ---- | ------------------------- | ------------------------------------- |
| 新字段  | `jobdescription.org_id`   | JD 归属组织；非空即组织共享，全组织成员可用于创建邀请          |
| 新字段  | `knowledgedoc.org_id`     | 知识文档归属组织；非空即企业知识库，进入本组织面试的 RAG 检索     |
| 新字段  | `candidateinvite.focus`   | 本次面试的考察重点（HR 自定义，随邀请落库）               |
| 新字段  | `interview.focus`         | 考察重点快照，面试时注入面试官 prompt                 |

> 均为新增列，由 `_run_migrations()` 幂等补齐，执行下面的 `init_db()` 即可完成迁移；
> 存量向量索引无需重建：RAG 以数据库归属为权威，检索出候选片段后再按 doc_id 二次过滤。

### v3.3 迁移内容（2026-09-17）

| 变更类型 | 对象                            | 说明                              |
| ---- | ----------------------------- | ------------------------------- |
| 新表   | `organization`                | 企业组织（HR 侧数据隔离边界）                |
| 新表   | `orgmember`                   | 组织成员（owner / hr / viewer）       |
| 新表   | `candidateinvite`             | 候选人面试邀请（免注册作答链接）                |
| 新表   | `candidate`                   | 候选人（关联 `role="candidate"` 的无密码用户） |
| 新字段  | `interview.org_id`            | 面试归属组织；个人练习恒为 NULL              |
| 修复   | `interview.stage`             | 补齐 SQLite 迁移列表中缺失的两列（此前仅 PG 有）  |
| 修复   | `interview.stage_updated_at`  | 同上                              |

> 新表由 `SQLModel.metadata.create_all` 自动创建，新字段由 `_run_migrations()` 幂等补齐，
> 因此本次仍只需执行下面的 `init_db()` 即可完成迁移。

## 七、常用命令速查

### 服务管理

```bash
# 启动所有服务
docker compose -f docker-compose.prod.yml up -d

# 停止所有服务
docker compose -f docker-compose.prod.yml down

# 重启单个服务
docker compose -f docker-compose.prod.yml restart backend

# 查看服务状态
docker compose -f docker-compose.prod.yml ps

# 查看实时日志
docker compose -f docker-compose.prod.yml logs -f backend
docker compose -f docker-compose.prod.yml logs -f nginx
```

### 数据库操作

```bash
# 连接 PostgreSQL
docker compose -f docker-compose.prod.yml exec postgres psql -U postgres -d ai_interviewer

# 备份数据库
docker compose -f docker-compose.prod.yml exec postgres pg_dump -U postgres ai_interviewer > backup.sql

# 恢复数据库
cat backup.sql | docker compose -f docker-compose.prod.yml exec -T postgres psql -U postgres -d ai_interviewer
```

### 数据管理

```bash
# 查看数据目录
ls -la /opt/ai-interviewer/data/

# 备份向量库
tar -czf chroma_backup.tar.gz /opt/ai-interviewer/data/chroma_db/

# 备份知识库
tar -czf knowledge_backup.tar.gz /opt/ai-interviewer/data/knowledge/
```

## 八、回滚方案

若新版本出现问题，执行以下步骤回滚：

```bash
cd /opt/ai-interviewer

# === 1. 找到最近的备份 ===
LATEST_DIST=$(ls -d dist.bak.* 2>/dev/null | sort -r | head -1)
LATEST_SERVER=$(ls -d server.bak.* 2>/dev/null | sort -r | head -1)

# === 2. 恢复 ===
if [ -n "$LATEST_DIST" ]; then
    rm -rf dist
    mv "$LATEST_DIST" dist
fi

if [ -n "$LATEST_SERVER" ]; then
    rm -rf server
    mv "$LATEST_SERVER" server
fi

# === 3. 重建并重启 ===
docker compose -f docker-compose.prod.yml build --no-cache backend
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d

# === 4. 数据库回滚（如需）===
# 使用 pg_dump 备份恢复
```

## 十、故障排查

### 常见问题

| 问题         | 原因               | 解决方案                                      |
| ---------- | ---------------- | ----------------------------------------- |
| 后端容器重启失败   | `server.main` 缺失 | `docker compose build --no-cache backend` |
| 前端显示 502   | Nginx 找不到后端      | 检查后端容器是否运行                                |
| API 返回 500 | 数据库未迁移           | 执行 `migrate_postgres()`                   |
| 向量库 400    | 文档超长             | 检查文档是否 ≤ 500 字                            |
| SSL 证书错误   | 证书路径无效           | 使用 `certifi.where()`                      |

### 日志查看

```bash
# 后端错误日志
docker compose -f docker-compose.prod.yml logs backend 2>&1 | grep -i error

# Nginx 访问日志
docker compose -f docker-compose.prod.yml exec nginx tail -f /var/log/nginx/access.log

# PostgreSQL 日志
docker compose -f docker-compose.prod.yml exec postgres tail -f /var/log/postgresql/postgresql-*.log
```
