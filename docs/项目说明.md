# 具身面试官 · 项目说明

> 赛题：**让 AI「活」起来 —— 基于魔珐星云具身交互智能 SDK 的创新应用**（开源 AI 工具赛道）
> 项目：AI 面试官（`ai-interviewer`）· 开源许可 MIT

---

## 一、一句话介绍

**具身面试官**是一个以 3D 具身交互智能体为交互界面、以 LLM + RAG 为大脑、以 Function Calling 为手脚的面试训练智能体。

它不只"问问题、给评分"，而是**把面试官这个人演出来**——包括他的表情、语气、肢体语言，以及最重要的：**他对你回答的即时态度**。

---

## 二、赛题自由度覆盖

赛题要求"作品自由度应至少覆盖表达层，灵活组合其他自由度"。本项目**三层全覆盖**：

| 自由度 | 赛题定义 | 本项目实现 | 代码位置 |
|---|---|---|---|
| **表达层** | 有温度的多模态呈现界面 | 流式分段播报、SSML、字幕、口型同步、具身状态（聆听/思考/说话） | `src/providers/digitalAvatarProvider.ts` |
| **交互层** | 可双向沟通的对话载体 | 面试官大脑（LLM）+ RAG 题库检索 + 多轮追问 + 打断 + 简历/JD 定向提问 | `server/services/interview_brain_service.py` |
| **行动层** | 可执行任务的 Agent 载体 | 11 个 Function Calling 工具 + 判题 + 多模态 Widget 实时呈现执行结果 | `server/services/interview_tools.py` |

## 三、目标用户与痛点

| 用户 | 真实痛点 |
|---|---|
| 校招 / 社招求职者 | 技术会，但一开口就崩；缺练习对象，真人模拟面试成本高且约不到 |
| 转行人群 | 需要高频、低压、可重复的练习机会，但每次失败都伴随真实社交成本 |
| 高校就业中心 / 培训机构 | 师资有限，无法做到"人手一面的高频模拟" |

**痛点本质**：面试是一项**表达技能**，而绝大多数 AI 工具把它当成**知识问答**在处理。

## 四、技术架构

### 4.1 总体架构

```
┌──────────────────────────── 浏览器端（Vue 3 + TypeScript + Vite）────────────────────────────┐
│                                                                                             │
│  InterviewView / ChatView                                                                   │
│    ├── 具身交互智能体 SDK @xmov/avatar（WebGL2 端侧渲染）                                      │
│    │      ├── 姿态：listen() / think() / speak() / interactiveidle() / interrupt()            │
│    │      ├── 字幕：proxyWidget.subtitle_on / subtitle_off                                   │
│    │      └── Widget：proxyWidget（13 类事件）→ WidgetHost + 6 个业务卡片                       │
│    ├── SSE 事件订阅（工具/Widget/情绪/延迟指标）                                                │
│    └── 降级链路：Lottie 形象 + Web Speech（ASR/TTS）                                           │
└───────────────────────────────────┬─────────────────────────────────────────────────────────┘
                                    │ WebSocket（SDK 直连星云网关）
                                    ▼
┌────────────────── 魔珐星云 E2E Server / TTSA（云端）──────────────────┐
│  ASR 识别 · 分句与流式合成 · 口型与表情（face_ka_v2）· 关键动作 KA      │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ brain_config 回调（OpenAI 兼容 SSE）
                                ▼
┌──────────────────── 后端 FastAPI（server/）────────────────────┐
│  brain proxy      /api/avatar/brain-proxy/v1/chat/completions  │  ← 按 token 分流为「面试大脑」
│  面试编排         /api/interview/*（start / answer / submit-code / end）│
│  事件总线 SSB     /api/interview/{id}/events                   │
│  Function Calling 11 个工具 + 流式工具循环                      │
│  知识/简历/JD     RAG 检索 · 简历解析 · 人岗匹配                 │
│  判题             Judge0 CE · 报告生成                          │
└───────┬──────────────────────┬───────────────────────┬─────────┘
        │                      │                       │
   PostgreSQL 16 / SQLite   ChromaDB（向量库）     外部 API
```

### 4.2 两条对话链路

| | 语音链路 | 文字链路 |
|---|---|---|
| 入口 | SDK 内置 ASR → E2E Server → 本后端 brain proxy | 前端直接调 `/api/interview/{id}/answer` |
| 工具调用 | ✅ 11 个工具可用 | ✅ `/answer`、`/submit-code` 命令流可触发 |
| 情绪/表情 | ✅ 由 `set_emotion` 工具驱动 | ⚠️ 无 |
| 依赖 | `AVATAR_PROXY_BASE_URL` 须为公网可达地址（E2E Server 回调） | 无额外要求 |

> **诚实声明**：两条链路当前能力不对等（语音有工具与情绪、文字有完整流程控制），统一到 brain 的工作已列入下一步计划。

### 4.3 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite 6 + Pinia + TailwindCSS + vue-i18n + Monaco Editor |
| 具身交互 | 魔珐星云 `@xmov/avatar`（Agent 模式，WebGL2 端侧渲染） |
| 后端 | FastAPI + SQLModel + Uvicorn（Python 3.12） |
| 数据 | PostgreSQL 16 / SQLite（默认）+ ChromaDB 向量库 |

| 跨端 | Capacitor 7（iOS / Android）+ 微信小程序壳工程 |

## 五、关键实现

### 5.1 面试大脑：让具身交互智能体"知道自己是谁"

具身交互智能体的对话由**云端 E2E Server 回调应用侧 brain 代理**完成。本项目通过**面试专用 token** 把回调分流到"面试官大脑"：

1. 面试开始时后端签发一次性 `interviewavatarsession` token（`POST /api/interview/{id}/avatar-session`）；
2. 前端把该 token 连同 `brain_config`（`provider: openai` + 代理 `base_url`）交给 SDK；
3. E2E Server 带 token 回调本后端 `/api/avatar/brain-proxy/v1/chat/completions`；
4. 后端按 token 判定这是面试会话 → 注入**面试官 system prompt**（含岗位、难度、风格）→ 走面试大脑。

代码：`server/routers/avatar.py`、`server/routers/interview.py`、`server/services/interview_brain_service.py`。

### 5.2 Function Calling：让面试官"能办事"

11 个工具（`server/services/interview_tools.py`）：

| 工具 | 作用 | 产出 Widget |
|---|---|---|
| `get_job_description` | 读取目标岗位 JD | — |
| `analyze_resume` | 解析简历要点 | ResumeHighlight |
| `match_resume_to_jd` | 人岗匹配打分 | MatchScore |
| `retrieve_knowledge` | RAG 检索题库 | — |
| `pick_algorithm_problem` | 抽算法题 | QuestionCard |
| `run_code` | Judge0 判题 | JudgeResult |
| `score_answer` | 单题评分 | Score |
| `get_interview_progress` | 剩余时间/进度 | — |
| `generate_report` | 生成评估报告 | InterviewReport |
| `set_emotion` | **设置本轮情绪与关键动作** | — |
| `play_action` | **触发关键动作（KA）** | — |

后两个是本方案与"纯文本方案"的分界线：**LLM 的语义判断直接落到表情与身体动作上**。

流式工具循环的关键实现细节：分片 `tool_calls` 需按 `index` 累积后再解析、工具耗时用过场语掩盖（同时触发 `think()`）、`max_rounds=3` 防死循环、数据库操作使用独立 `Session`。

### 5.3 具身状态与打断

| 面试阶段 | SDK 调用 |
|---|---|
| 等待候选人开口 | `listen()` |
| 候选人答完、LLM 生成中 | `think()`（覆盖首 token 前的空窗） |
| 面试官发言 | `speak()`（由 TTSA 流式驱动） |
| 等待候选人写代码 | `interactiveidle()` |
| 候选人插话 | `interrupt()`（端侧即时停嘴，异步等待） |
| 结束 | `idle()` → `interrupt` → `offlineMode` → `destroy`（强制顺序） |

### 5.4 多模态 Widget：结果不是"说出来"，而是"边说边呈现"

SDK 的 `proxyWidget` 按 `data.type` 精确匹配，本项目接管 13 类事件（TTSA 的 `widget_*` 与官方文档的 `show_*` 两套命名并存），并落地 6 个业务卡片：简历要点、人岗匹配、算法题卡、判题结果、即时评分、面试报告。

> 设计取舍：**不使用 `onWidgetEvent`**。官方陷阱清单记载它会禁用 SDK 内部全部 UI 渲染（含行走的 canvas 偏移），改用 `proxyWidget` 可保留 SDK 默认行为。

### 5.5 事件总线与可观测

后端在工具循环中向 SSE 旁路端点 `GET /api/interview/{id}/events` 广播结构化事件（`tool_start` / `tool_result` / `widget` / `emotion` / `metrics`），前端据此实时推 Widget、驱动延迟面板（首字延迟、工具耗时、端到端耗时、事件流连接状态）。

### 5.6 知识、简历与判题

- **题库**：Markdown 解析按 ≤500 字分块 → bge-m3 Embedding → ChromaDB；检索支持按岗位/难度预过滤，无命中则全库检索。
- **简历/JD**：PDF/Word 解析，AI 提取要点并进行人岗匹配评估。
- **判题**：Judge0 CE 公共 API，返回逐用例结果并由面试官同步讲解失败用例。

### 5.7 降级链路

SDK 初始化失败或浏览器不支持 WebGL2 → 回落 Lottie 动画形象 + Web Speech（ASR/TTS），保证低端设备与无障碍场景仍可用。销毁、打断、姿态接口在降级实现中均为 no-op，保持调用方无需分支。

## 六、创新点

1. **情绪由 LLM 决策，而不是预设动画轮播**
   把"情绪"做成 `set_emotion` 工具，LLM 对回答质量的语义判断 → 写入本轮首帧 `extra.emotion` 驱动表情（`face_ka_v2`）+ 在文本流注入 `<ue4event ka>` 驱动关键动作。表情与语义对齐，而非固定循环。

2. **打断是真的即时打断**
   端侧 `enableClientInterrupt` + `interrupt()` 立即停嘴，并同步清理播报状态与后端已生成内容。相较云端视频流方案（2~5 秒），插话练习在训练中才成立。

3. **执行结果边说边呈现**
   判题、匹配、题卡等结构化结果不是打成一段文字，而是以 Widget 卡片在具身交互智能体的同时弹出；SSE 事件总线保证与播报同步。

4. **"确定性交互"与"LLM 推理"分工**
   LLM 的算力全部留给"评价回答"这件事；候选人的元选择（跳过、换题、看提示）走不带 LLM 的确定性控件路径（设计中，见第八节）。

> 更完整的"为什么非具身不可"论证（含与纯文本/纯语音方案的逐项对比、消融实验设计）见 [赛题二-场景创意论证.md](赛题二-场景创意论证.md)。

## 七、能力现状与边界

本项目坚持**把未验证的部分明确标出**，不把"链路就位"当成"功能可用"。

### 7.1 已实现并有实测证据

| 能力 | 证据 |
|---|---|
| 面试大脑分流（token → 面试官 prompt） | 日志命中 `[Brain Proxy] Auth OK (interview)`；真实 LLM 以面试官身份出题并落库 |
| 11 个 Function Calling 工具 + 流式工具循环 | 11/11 注册；实调 7 个成功；分片 `tool_calls` 正确拼接 |
| 判题 | Judge0 真实返回用例结果（如 `0/3` + 失败用例） |
| 事件总线 + SSE | 50 秒连接稳定，keep-alive 正常，断开无异常 |
| Widget 客户端通道 | 文字路径实测推送 `judge_result` 成功 |
| 具身状态与打断清理 | 全量 `vue-tsc --noEmit` 通过；销毁顺序按官方规范 |

### 7.2 待验证（受环境限制）

| 能力 | 阻塞原因 |
|---|---|
| 语音链路端到端（ASR → brain → TTSA → 播报） | `AVATAR_PROXY_BASE_URL` 需公网可达，本地 `localhost` 物理不可达 |
| 表情（`face_ka_v2`）实际效果 | 依赖部署环境 `tts_config.support_emotion` 开放情况与音色情感标签集合 |
| KA 关键动作 | 动作名需从动作库穷举确认（不存在时后端返回 `deleted=true`） |
| `<uievent>` / `<ue4event>` 是否原样透传到 TTSA | Agent 模式下文本经 E2E Server 转发，穿透性未证实；未证实前 SSML 注入开关默认关闭 |

### 7.3 未实现

面试流程状态机、四类交互控件（Picker / Input / Text / Confirm）、行走（`walk_points`）、跨会话用户画像记忆、CI 之外的自动化测试。

## 八、运行与部署

完整步骤见 [README](../README.md) 与 [DOCKER.md](../DOCKER.md)。三种运行方式覆盖"有凭证 / 无凭证不想下载 / 无凭证也不想下载模型"三类环境：

```bash
# 方式一：云端凭证（功能最全，含具身播报）
cp .env.example .env        # 填入 LLM / Embedding / 具身交互智能体凭证
docker compose up -d --build

# 方式二：本地大模型（无任何凭证，AI 链路完整；首次下载约 2.5GB 模型）
docker compose -f docker-compose.yml -f docker-compose.local-llm.yml up -d --build

# 方式三：离线规则模式（零依赖、秒级启动；题库 + 规则，非大模型）
OFFLINE_MODE=true docker compose up -d --build
```

### 8.1 三种方式的能力对照

| 能力 | 方式一（云端凭证） | 方式二（本地模型） | 方式三（离线规则） |
|---|---|---|---|
| 出题 / 追问 / 点评 / 报告 | ✅ 云端大模型 | ✅ 本地 qwen2.5:3b | ⚠️ 内置题库 + 规则模板 |
| 题库 RAG 检索 | ✅ 向量检索 | ✅ 向量检索（本地 bge-m3） | ⚠️ 退化为关键词匹配 |
| 代码判题（Judge0 CE） | ✅ | ✅ | ✅（公网 API） |
| 具身播报（口型 / 表情 / 关键动作） | ✅ 魔珐云端 TTSA | ⚠️ 无凭证时降级 | ⚠️ 无凭证时降级 |
| 是否需要联网下载模型 | 否 | 是（约 2.5GB） | 否 |
| 是否需要账号 / Key | 是 | 否 | 否 |

> **具身播报依赖魔珐云端**，任何"零凭证"方案都无法替代，只能按既有的降级链路（Lottie 形象 + 浏览器 Web Speech）运行。
>
> 方式三为**规则实现而非大模型**：出题来自内置题库，评分由"回答长度 / 技术关键词覆盖 / 表达结构"等可解释规则计算。页面顶部会显示当前运行模式提示条（由后端 `GET /api/mode` 下发），避免把规则输出误认为模型能力。
