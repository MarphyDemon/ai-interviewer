## 1. 部署架构

```
┌─────────────────────────────────────────────────────┐
│                    服务器                             │
│                                                     │
│  ┌─────────┐  ┌──────────┐  ┌───────────────────┐  │
│  │ Nginx   │  │ FastAPI  │  │  PostgreSQL 16    │  │
│  │ 反向代理 │→│  :8000   │→│  :5432            │  │
│  └────┬────┘  └──────────┘  └───────────────────┘  │
│       │                                             │
│       │  /api/* 转发到 FastAPI                       │
│       │  /*      静态文件 (dist/)                    │
│                                                     │
│  存储：本地 data/ 目录 或 S3 对象存储                  │
└─────────────────────────────────────────────────────┘
```

**三种部署方式**：

| 方式 | 适用场景 | 复杂度 |
|------|----------|--------|
| **一键脚本** | 新手/快速上线，脚本自动处理一切 | ⭐⭐⭐ |
| **Docker Compose** | 熟悉 Docker，需要精细控制 | ⭐⭐ |
| **手动分步部署** | 无 Docker 环境，需要最大控制权 | ⭐ |

## 2. 服务器准备

### 2.1 推荐配置

| 项目 | 最低要求 | 推荐 |
|------|----------|------|
| OS | Ubuntu 20.04 / CentOS 7 / Alibaba Cloud Linux 2/3 | Ubuntu 22.04 LTS / Alibaba Cloud Linux 3 |
| CPU | 2 核 | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 40 GB | 100 GB SSD |
| 带宽 | 5 Mbps | 10 Mbps |

### 2.2 必需软件

| 软件 | 版本 | 用途 |
|------|------|------|
| Docker | 24+ | 容器化部署 |
| Docker Compose | v2+ | 多服务编排 |
| Node.js | 20+ | 前端构建 |

> 注：一键脚本会自动安装 Docker 和 Node.js，无需手动准备。

### 2.3 安全组 / 防火墙

需开放以下端口：

| 端口 | 服务 | 备注 |
|------|------|------|
| 80 | HTTP | Nginx，对外访问入口 |
| 443 | HTTPS | Nginx，跳转 HTTPS（可选） |

> 注：PostgreSQL(5432) 和 FastAPI(8000) 仅在 Docker 内网通信，无需对外暴露。

## 3. 方式一：一键脚本部署（最简单，推荐 ⭐⭐⭐）

此方式只需 **1 条命令**，脚本会自动完成：
- ✅ 检查并安装 Docker、Node.js
- ✅ 检查 `.env` 配置
- ✅ 构建前端产物
- ✅ 自动生成安全的密码和加密密钥
- ✅ 一键启动所有服务

### 3.1 上传项目到服务器

**⚠️ 不要直接上传整个 `./`**，会包含 node_modules(几百MB)、data、.git 等无用文件。

#### 方式 A：Git 拉取（最干净，推荐）⭐

```bash
# 在服务器上直接克隆
cd /opt
git clone <repo-url> ai-interviewer
cd ai-interviewer
```

#### 方式 B：打包上传（无 Git 仓库时）

在**本地 Windows** 执行，打包核心文件（排除 node_modules、data 等）：

```powershell
# Windows PowerShell：打包需要的文件
# 排除: node_modules, .git, data, pg, dist, .env

cd d:\ai项目\ai-Interviewer

# 使用 tar 打包（Windows 10+ 原生支持 tar）
tar -czf ai-interviewer-deploy.tar.gz ^
  --exclude=node_modules ^
  --exclude=.git ^
  --exclude=data ^
  --exclude=pg ^
  --exclude=dist ^
  --exclude=.env ^
  --exclude=.gitignore ^
  .

# 上传到服务器
scp ai-interviewer-deploy.tar.gz root@你的服务器IP:/opt/

# 在服务器上解压
cd /opt
mkdir -p ai-interviewer
tar -xzf ai-interviewer-deploy.tar.gz -C ai-interviewer/
cd ai-interviewer
```

#### 方式 C：rsync 增量同步（服务器间传输）

```bash
# 从另一台 Linux 服务器同步（排除大目录）
rsync -avz --exclude='node_modules' --exclude='.git' \
  --exclude='data' --exclude='pg' --exclude='dist' \
  ./ user@your-server:/opt/ai-interviewer/
```

### 3.2 配置环境变量

```bash
cd /opt/ai-interviewer

# 从模板创建配置文件
cp server/.env.example server/.env

# 编辑配置，填入真实的 API Key
nano server/.env
```

**必须填写的配置**：

| 配置项 | 说明 |
|--------|------|
| `LLM_API_KEY` | 深度求索 API Key |
| `EMBEDDING_API_KEY` | 硅基流动 API Key |

### 3.3 一键部署 🚀

```bash
cd /opt/ai-interviewer

# 赋予执行权限
chmod +x deploy.sh

# 一键部署！
./deploy.sh
```

### 3.5 数据同步（部署完成后）

如果本地已有数据（用户、面试记录、知识库等），按以下步骤同步到服务器：

```bash
# === 在本地电脑执行 ===

# 1. 停止本地服务（避免数据不一致）
# Windows: 关闭 FastAPI 进程或执行 net stop ai-interviewer-backend

# 2. 打包 data 目录
tar -czf ai-data-backup.tar.gz data/

# 3. 上传到服务器
scp ai-data-backup.tar.gz user@your-server:/opt/ai-interviewer/
```

```bash
# === 在服务器上执行 ===

# 4. 停止服务器上的服务
docker compose -f docker-compose.prod.yml down

# 5. 备份服务器上的空数据（防万一）
mv data/ data.empty_backup/

# 6. 解压上传的数据
tar -xzf ai-data-backup.tar.gz
# 解压后会得到 data/ 目录

# 7. 启动 PostgreSQL + 后端（迁移脚本在后端容器内执行）
docker compose -f docker-compose.prod.yml up -d postgres backend && sleep 5

# 8. 迁移数据库到 PostgreSQL（在后端容器内执行）
docker compose -f docker-compose.prod.yml exec backend python server/scripts/migrate_to_pg.py

# 9. 启动全部服务（含 Nginx）
docker compose -f docker-compose.prod.yml up -d && sleep 5

# 10. 重建向量索引（知识库搜索功能需要）
curl -X POST http://localhost/api/knowledge/reindex -H "Authorization: Bearer <admin_token>"

# 11. 验证数据
curl -s http://localhost/api/history | python -m json.tool | head -20
```

> 💡 **提示**：详细的数据迁移说明请参阅 [第 6 章](#6-本地数据迁移至服务器)。

### 3.6 管理服务

```bash
# 启动
docker compose -f docker-compose.prod.yml up -d

# 停止
docker compose -f docker-compose.prod.yml down

# 重启（代码更新后）
docker compose -f docker-compose.prod.yml restart

# 重新构建并部署（代码更新后）
./deploy.sh
```

## 4. 方式二：Docker Compose 手动部署

如果您需要更多控制，可以手动执行 Docker Compose 命令。

### 4.1 安装 Docker

```bash
# Ubuntu 22.04
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker
```

### 4.2 上传并配置项目

```bash
git clone <repo-url> /opt/ai-interviewer
cd /opt/ai-interviewer

# 创建环境配置
cp server/.env.example server/.env
# 编辑填入 API Key
nano server/.env

# 构建前端
npm install
npm run build:web
```

### 4.3 修改 docker-compose.prod.yml

编辑 `docker-compose.prod.yml`，可自定义：
- `POSTGRES_PASSWORD`: 数据库密码
- 端口映射
- 数据卷挂载路径

### 4.4 启动服务

```bash
# 启动
docker compose -f docker-compose.prod.yml up -d --build

# 查看状态
docker compose -f docker-compose.prod.yml ps

# 查看日志
docker compose -f docker-compose.prod.yml logs -f

# 停止
docker compose -f docker-compose.prod.yml down
```

### 4.5 开发模式（可选）

如需开发调试，可使用开发模式的 `docker-compose.yml`：

```bash
# 开发模式包含 Vite Dev Server (port 5173)
docker compose up -d

# 访问 http://localhost:5173
```

## 5. 方式三：手动分步部署

### 5.1 安装 PostgreSQL

```bash
# Ubuntu
sudo apt update
sudo apt install postgresql-16

# 创建数据库和用户
sudo -u postgres psql
```

```sql
CREATE USER ai_app WITH PASSWORD 'your_secure_password';
CREATE DATABASE ai_interviewer OWNER ai_app;
GRANT ALL PRIVILEGES ON DATABASE ai_interviewer TO ai_app;
```

### 5.2 部署后端

```bash
cd /opt/ai-interviewer
python -m venv .venv
source .venv/bin/activate
pip install -r server/requirements.txt

# 使用 systemd 管理后端服务
cat > /etc/systemd/system/ai-interviewer.service << 'EOF'
[Unit]
Description=AI Interviewer Backend
After=network.target postgresql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/ai-interviewer
EnvironmentFile=/opt/ai-interviewer/server/.env
ExecStart=/opt/ai-interviewer/.venv/bin/uvicorn server.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable ai-interviewer
sudo systemctl start ai-interviewer
```

### 5.3 部署前端

```bash
cd /opt/ai-interviewer
npm install
npm run build:web
```

### 5.4 配置 Nginx

```bash
sudo cat > /etc/nginx/sites-available/ai-interviewer.conf << 'EOF'
server {
    listen 80;
    server_name your-domain.com;

    root /opt/ai-interviewer/dist;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript image/svg+xml;
    gzip_min_length 1000;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_connect_timeout 75s;
    }

    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
EOF

sudo ln -s /etc/nginx/sites-available/ai-interviewer.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## 6. 本地数据迁移至服务器

### 6.1 需要迁移的数据

| 数据类型 | 路径 / 位置 | 说明 |
|----------|-------------|------|
| 业务数据 | `data/` | 用户、面试记录、报告、题库等 |
| 知识库文件 | `data/knowledge/` | 上传的 Markdown 题库文档 |
| 简历文件 | `data/resumes/` | 用户上传的简历 PDF/Word |
| 录制文件 | `data/recordings/` | 面试录制音频 |
| 环境配置 | `server/.env` | API Key 等敏感配置（手动填写） |

### 6.2 迁移步骤

#### 步骤 1：在本地导出数据

```bash
# 打包 data 目录
tar -czf ai-interviewer-data-$(date +%Y%m%d).tar.gz data/
```

#### 步骤 2：上传到服务器

```bash
scp ai-interviewer-data-*.tar.gz user@your-server:/opt/ai-interviewer/
```

#### 步骤 3：在服务器上解压

```bash
cd /opt/ai-interviewer
tar -xzf ai-interviewer-data-*.tar.gz
```

#### 步骤 4：迁移数据库（如果服务器用 PostgreSQL）

**根据部署方式选择对应的命令：**

```bash
# === Docker 部署（方式一/二）===
# 确保 PostgreSQL 容器正在运行
docker compose -f docker-compose.prod.yml up -d postgres
# 在后端容器内执行迁移
docker compose -f docker-compose.prod.yml exec backend python server/scripts/migrate_to_pg.py

# === 手动部署（方式三）===
cd /opt/ai-interviewer
source .venv/bin/activate
python server/scripts/migrate_to_pg.py
```

#### 步骤 5：重建向量索引

```bash
# 启动后端后调用 API
curl -X POST http://localhost/api/knowledge/reindex -H "Authorization: Bearer <admin_token>"
```

#### 步骤 6：验证数据完整性

```bash
# 检查文件数量
find data/knowledge -type f | wc -l
find data/resumes -type f | wc -l

# API 验证
curl -s http://localhost/api/knowledge | python -m json.tool | head -20
```

### 6.3 S3 存储方案（可选）

如果使用 S3 兼容对象存储：

```bash
# 配置 S3
cat >> server/.env << 'EOF'
S3_ENDPOINT=https://your-s3-endpoint.com
S3_ACCESS_KEY=your_access_key
S3_SECRET_KEY=your_secret_key
S3_BUCKET=ai-interviewer

# 上传现有文件
aws s3 sync data/knowledge/ s3://your-bucket/knowledge/
aws s3 sync data/resumes/ s3://your-bucket/resumes/
aws s3 sync data/recordings/ s3://your-bucket/recordings/
```

## 7. HTTPS 与域名配置

### 7.1 使用 Certbot 配置 Let's Encrypt

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com -d www.your-domain.com
sudo certbot renew --dry-run
```

### 7.2 配置 Nginx HTTPS

```bash
# 对于 Docker 部署，修改 deploy/nginx.conf 添加 SSL 配置
# 或者在 Docker 外使用宿主机 Nginx 处理 SSL
```

```nginx
# 外部 Nginx 配置示例
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # 反代到 Docker Nginx
    location / {
        proxy_pass http://127.0.0.1:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 7.3 小程序/移动端域名配置

**微信小程序**（[mp.weixin.qq.com](https://mp.weixin.qq.com)）：
- 业务域名：`https://your-domain.com`
- request 合法域名：`https://api.your-domain.com`
- socket 合法域名：`wss://your-domain.com`

**Capacitor App**：
- 无需额外域名配置

## 9. 备份与恢复

### 9.1 备份脚本

在服务器上创建 `/opt/ai-interviewer/scripts/backup.sh`：

```bash
#!/bin/bash
BACKUP_DIR=/backup/ai-interviewer
DATE=$(date +%Y%m%d_%H%M%S)

mkdir -p $BACKUP_DIR

# PostgreSQL 备份
pg_dump -U postgres ai_interviewer | gzip > $BACKUP_DIR/db_$DATE.sql.gz

# 文件备份
tar -czf $BACKUP_DIR/files_$DATE.tar.gz /opt/ai-interviewer/data/

# 清理 30 天前的备份
find $BACKUP_DIR -name "*.gz" -mtime +30 -delete

echo "Backup completed: $DATE"
```

### 9.2 设置定时备份

```bash
# /etc/cron.d/ai-interviewer-backup
echo "0 3 * * * root /opt/ai-interviewer/scripts/backup.sh" > /etc/cron.d/ai-interviewer-backup
```

### 9.3 恢复流程

```bash
# 恢复数据库
gunzip -c /backup/ai-interviewer/db_YYYYMMDD.sql.gz | \
  sudo -u postgres psql -d ai_interviewer

# 恢复文件
tar -xzf /backup/ai-interviewer/files_YYYYMMDD.tar.gz -C /opt/ai-interviewer/

# 重启服务
sudo systemctl restart ai-interviewer
```

## 10. 常见问题排查

### Q1：一键脚本报 "缺少 API Key"？

```bash
# 检查 server/.env 文件
cat server/.env | grep _KEY

# 确认格式（不能有尖括号占位符）
# 错误: LLM_API_KEY=<填入>
# 正确: LLM_API_KEY=sk-xxxxxxxxxxxx
```

### Q2：后端报 "connection refused"？

```bash
# Docker 部署
docker compose -f docker-compose.prod.yml ps
# 确认 postgres 容器已启动

# 查看后端日志
docker compose -f docker-compose.prod.yml logs backend
```

### Q3：前端页面空白 / API 404？

```bash
# 检查 Nginx 配置
docker compose -f docker-compose.prod.yml exec nginx nginx -t

# 检查前端产物
ls -la dist/

# 直接测试后端
curl http://localhost:8000/docs
```

### Q4：端口 80 被占用？

```bash
# 检查占用
sudo lsof -i :80

# 停止占用进程
sudo systemctl stop nginx   # 如果宿主机有 Nginx

# 或修改 docker-compose.prod.yml 端口映射
# ports:
#   - "8080:80"
```

### Q5：权限问题？

```bash
# 修复数据目录权限
chmod -R 755 data/
chown -R $(whoami) data/
```

### Q6：更新代码后如何重新部署？

```bash
# 拉取最新代码
git pull

# 重新运行一键脚本（会自动构建和重启）
./deploy.sh
```
