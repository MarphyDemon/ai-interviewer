## 一、测试金字塔架构

```
┌─────────────────────────────────────────────────────────┐
│  Layer 4: E2E 端到端（Playwright）                        │
│  覆盖核心业务流程 + 管理后台 CRUD                         │
│  执行时机：MR 触发 @smoke / 合并主分支 @regression         │
├─────────────────────────────────────────────────────────┤
│  Layer 3: 组件测试（Playwright Component Tests）           │
│  覆盖核心交互组件（ChatView、AdminKnowledge 等）            │
│  执行时机：与 E2E 同 Pipeline 并行                         │
├─────────────────────────────────────────────────────────┤
│  Layer 2: 后端 API 测试（pytest + httpx）                 │
│  覆盖非 AI 路由全量 + AI 路由冒烟                          │
│  执行时机：独立 Pipeline 或与 E2E 串行                     │
├─────────────────────────────────────────────────────────┤
│  Layer 1: 数据层（临时 SQLite 文件数据库）                  │
│  快速初始化 + 自动清理                                    │
└─────────────────────────────────────────────────────────┘
```

### 3.1 测试环境架构


> **说明**：Vite dev server 运行在本地（通过 Playwright `webServer` 自动启动），

```typescript
    username: 'admin',
    password: 'AdminPass123',

export async function createTestUser(
  request: APIRequestContext
): Promise<{ token: string; userId: number }> {
  const res = await request.post(`${BASE_URL}/api/auth/register`, {
    data: testUsers.standard,
  })
  const { token, user } = await res.json()
  return { token, userId: user.id }
}

export async function cleanupTestUser(
  request: APIRequestContext,
  userId: number
): Promise<void> {
  await request.delete(`${BASE_URL}/api/admin/users/${userId}`)
}
```

### 3.6 启动测试环境

```bash
# 1. 启动测试环境
docker compose -f docker-compose.test.yml up -d

# 2. 等待数据库就绪
sleep 5

# 3. 初始化数据库
docker compose -f docker-compose.test.yml exec test-backend python -c "
from server.database import init_db
init_db()
"

# 4. 运行 E2E 测试
npx playwright test

# 5. 清理环境
docker compose -f docker-compose.test.yml down -v
```

### 4.2 标签体系

| 标签 | 用途 | 超时 | 执行时机 |
|------|------|------|----------|
| `@smoke` | 核心冒烟（登录+主页） | 2min | MR 触发 |
| `@regression` | 全量回归（含 AI） | 5min | 合入主分支 |
| `@desktop` | 桌面浏览器测试 | 1min | 默认 |
| `@mobile` | 移动端视口测试 | 1min | 配合 @desktop |
| `@ai` | AI 相关测试（真实 LLM） | 5min | @regression 时执行 |
| `@flaky` | 不稳定测试（标记重试） | 按实际 | 重试 2 次 |
| `@visual` | 视觉回归（预留） | 1min | 后续扩展 |

## 九、风险缓解策略

### 9.1 AI 响应不稳定

| 风险 | 缓解措施 |
|------|----------|
| LLM API 超时 | 超时设为 60s，`@ai` 标记允许 `@flaky` 重试 2 次 |
| LLM 响应格式变化 | 断言用 `toContain` 而非精确匹配，验证关键信息存在 |
| 速率限制（Judge0 CE） | 代码判题测试加 `sleep 2s` 间隔，或标记 `@skip-if-rate-limited` |

### 9.2 环境问题

| 风险 | 缓解措施 |
|------|----------|
| Docker 未启动 | CI 中检查 Docker 服务状态，失败提前终止并输出友好提示 |
| 浏览器下载失败 | `npm run test:install` 预下载，CI 缓存 Playwright 浏览器 |
| 数据库连接超时 | `globalSetup` 中轮询等待 API 就绪（最多 30s） |

### 9.3 测试数据污染

| 风险 | 缓解措施 |
|------|----------|
| 测试账号残留 | 用例内自创建自清理 + `globalTeardown` 批量清理 |
| 数据跨用例影响 | 每个 `describe` 用独立账号，`beforeEach` 登录、`afterEach` 登出 |
| 清理失败 | 用唯一 ID 前缀（如 `test_user_<timestamp>`），便于手动清理 |

### 9.4 选择器失效

| 风险 | 缓解措施 |
|------|----------|
| UI 变更导致选择器失效 | 集中在 `selectors.ts` 管理，一处修改全局生效 |
| 动态 ID 不可靠 | 优先使用 `getByRole`/`getByLabel`/`getByTestId` |
| 多语言影响 | 用 `data-testid` 属性标记关键元素，不受语言切换影响 |

## 附录 B：常见问题排查

| 问题 | 排查步骤 |
|------|----------|
| 测试卡在 `webServer` 启动 | 检查 Vite dev server 是否能正常启动；检查端口 5173 是否被占用 |
| `browserType.launch: Executable doesn't exist` | 运行 `npx playwright install chromium` 重新安装浏览器 |
| 断言超时但手动正常 | 增加 `actionTimeout`/`navigationTimeout`；检查是否有 loading 动画未消失 |
| AI 测试全部失败 | 检查 LLM API Key 是否有效；手动调用 API 确认服务正常 |
| 测试报告无法打开 | 直接打开 `test-results/index.html`；或运行 `npx playwright show-report` |
| Docker 环境启动失败 | 检查 Docker Desktop 是否运行；`docker compose logs test-backend` 查看日志 |
