## 2. 系统架构

浏览器前端（Vue3）通过 HTTP 调用后端（FastAPI）。后端 Service 层统一编排：题库解析（Markdown 分块 + Embedding 入 Chroma）、简历解析（PDF/Word 提取文本）、LLM 编排（DeepSeek，OpenAI 兼容协议）、RAG 检索（Chroma 向量检索）、报告生成。具身交互智能体 SDK 在浏览器端直接连接星云 TTSA 网关（WebSocket），凭证由后端 .env 代理下发。降级模式下使用 Lottie 动画 + Web Speech API。

关键外部依赖：
- DeepSeek API — LLM 编排（出题、追问、判卷、点评）
- 硅基流动 API — bge-m3 embedding（题库向量化）
- 星云 TTSA 网关 — 具身交互智能体驱动（语音 + 口型渲染）

### 3.3 面试状态机（Pinia Store）

状态枚举：idle（等待开始）、initializing（具身交互智能体初始化中）、asking（面试官提问中）、waiting_answer（等待用户回答）、analyzing（AI 分析中）、followup_asking（追问中）、generating_report（生成点评中）、finished（已结束）、error。

状态流转在 useInterview composable 中驱动，每次状态变更同步到后端记录对话。追问层级计数到 2 后强制换题。

### 3.4 具身交互智能体集成（主模式）

#### 3.4.1 统一接口设计

AvatarProvider 接口定义：init(containerId)、speak(text)、startASR()、stopASR()、interrupt()、idle()、destroy()。

InterviewerContainer.vue 根据浏览器能力检测自动选择 DigitalAvatar 或 Lottie 实现，业务层只调用统一接口。

#### 3.4.2 具身交互智能体实现

DigitalAvatarProvider 使用 XingyunAvatarAgent（@xmov/avatar/agent）：
- init：从后端 GET /api/avatar/config 获取凭证，new XingyunAvatarAgent({ containerId, appId, appSecret, gatewayServer, onMessage, agentCallbacks: { onASRResult, onAgentStateChange, onSpeakStateChange, onError, ... } })，调 agent.init({ onDownloadProgress })
- speak：调 agent.speakByE2E(text) 驱动具身交互智能体播报（接收纯文本，非 SSML）
- startASR/stopASR：调 agent.startASR()/stopASR()，ASR 结果通过 agentCallbacks.onASRResult 回调（载荷 { text, isFinal, raw }）
- interrupt：调 agent.interruptConversation()
- idle：调 agent.idle()（继承自父类 XmovAvatar）
- destroy：调 agent.destroy()
- 注意：onMessage（父类必填回调）仅接收 SDKError 错误消息；ASR/LLM/对话状态等业务事件全部走 agentCallbacks

#### 3.4.3 凭证安全

具身交互智能体 appId / appSecret / gatewayServer 属敏感信息，**不写在前端代码或文档中**，统一通过后端代理下发（GET /api/avatar/config，后端从 .env 读取）。.env 文件加入 .gitignore。

.env 示例（不入库）：

    AVATAR_APP_ID=<填入实际值>
    AVATAR_APP_SECRET=<填入实际值>
    AVATAR_GATEWAY_SERVER=https://nebula-agent.xingyun3d.com/user/v1/ttsa_v2/session

#### 3.4.4 Lottie 降级实现

LottieAvatarProvider 使用 vue3-lottie 加载动画 JSON。speak() 时触发嘴部动效 + 调用 TTS Provider 语音播报 + 显示字幕。startListening/stopListening 调用 ASR Provider。

降级判断条件：
- navigator.userAgent 检测浏览器版本不满足 WebGL2 / WebCodecs
- 具身交互智能体 SDK init() 失败（网络/凭证/资源下载异常）

### 3.5 语音抽象层

#### ASR Provider（语音识别）

ASRProvider 接口：start(onResult)、stop()。

| 实现 | 场景 |
|------|------|
| SdkAsrProvider | 主模式：复用具身交互智能体 SDK 的 startASR/stopASR，结果通过 agentCallbacks.onASRResult 回调 |
| WebSpeechAsrProvider | 降级模式：浏览器原生 SpeechRecognition |

#### TTS Provider（语音播报）

TTSProvider 接口：speak(text, onEnd)、cancel()。

| 实现 | 场景 |
|------|------|
| SdkTtsProvider | 主模式：具身交互智能体 speakByE2E 即负责 TTS |
| WebSpeechTtsProvider | 降级模式：浏览器原生 speechSynthesis |

### 3.6 响应式策略

TailwindCSS 断点：
- 移动端（< 768px）：单列布局，具身交互智能体区域顶部固定高度，对话区域下方滚动
- 平板（768px – 1024px）：过渡布局
- 桌面（> 1024px）：左右分栏，左侧具身交互智能体 + 面试状态，右侧对话 + 输入

移动端特殊处理：
- AnswerInput 默认语音模式，文字输入折叠为次要入口
- 具身交互智能体区域高度自适应视口，避免挤压对话区
- 触摸友好的按钮尺寸（≥ 44px）

### 4.3 题库解析与向量化

1. 上传 .md 文件 → 存入 data/knowledge/
2. markdown_parser 解析 frontmatter（position/difficulty/tags）+ 按标题层级（#/##/###）分块
3. 每块调硅基流动 bge-m3 API 生成 embedding
4. 存入 Chroma（metadata 含 doc_id, position, difficulty, tags, chunk_index）
5. 异步处理，通过 status 接口轮询

### 4.4 简历解析

1. 上传 PDF/Word → 存入 data/resumes/
2. pdf_parser（pdfplumber）或 docx_parser（python-docx）提取纯文本
3. 调 LLM 做轻量分析：结构完整度评分 + 与目标岗位匹配度初评
4. 结果存入 resumes 表

### 4.5 RAG 检索流程

1. 根据当前岗位 + 难度 + 对话上下文，构造检索 query
2. Chroma 按 metadata 过滤（position + difficulty）+ 向量相似度 top-k 检索
3. 检索到的知识块作为 LLM 出题/判卷的上下文素材

## 5. LLM 编排

### 5.1 多厂商抽象

使用 openai Python SDK（兼容 DeepSeek 及其他 OpenAI 兼容 API），通过管理页配置的 base_url / api_key / model 动态创建 client。

### 5.2 面试编排 Prompt 结构

面试编排通过结构化 JSON 输出控制状态机。

System Prompt 核心要素：
- 角色定义：你是面试官，正在面试 {岗位} {难度} 级别候选人
- 风格：{面试官风格}
- 知识素材：{RAG 检索到的知识块}
- 简历信息：{简历解析文本}（如有）
- 对话历史：{已有对话}
- 输出格式：JSON，含 action（ask/followup/next_question/end）、content（提问文本）、reasoning（内部判断）

### 5.3 点评 Prompt

面试结束后，将完整对话历史 + 简历信息 + 检索到的知识块一次性传给 LLM，要求输出结构化点评 JSON：
- total_score：总分
- dimension_scores：各维度评分（专业知识、表达逻辑、人岗匹配、应变能力、技术深度）
- summary：总评文字
- per_question_reviews：逐题点评数组（题目、用户回答、点评、参考答案、得分）
- resume_review：简历评分（结构完整度、岗位匹配度、亮点、短板）
- job_fit：人岗匹配综合评估

### 5.4 时长控制

面试创建时记录 start_time + duration。每次 AI 响应前检查剩余时间：
- 剩余 > 0：正常出题/追问
- 剩余 ≤ 0：强制 action=end，触发报告生成

前端 vite.config.ts 配置代理将 /api 转发到 http://localhost:8000。

### 8.2 Docker Compose（服务器部署）

    version: "3.8"

        build: .

## 9. 安全考虑

| 风险 | 措施 |
|------|------|
| 具身交互智能体凭证泄露 | 仅存后端 .env，前端通过代理获取，.env 入 .gitignore |
| LLM api_key 暴露 | 仅存后端，前端不直连 LLM；管理页展示时脱敏 |
| 管理页未授权 | 环境变量口令校验 |
| 麦克风权限 | 部署时强制 HTTPS；本地 localhost 可用 |
| 文件上传安全 | 限制文件类型（.md/.pdf/.docx）、大小上限、存储路径隔离 |
