# AI 面试官 · 需求文档

> 版本：v1.0 · 2026-08-11
> 状态：已确认，待开发

## 1. 项目概述

### 1.1 一句话定位

一款基于 AI 数字人的模拟面试平台：用户上传简历、选择岗位方向，由数字人面试官按题库知识点和简历内容进行语音/文字问答，结束后输出多维度点评报告。

### 1.2 核心价值

- **真实面试感**：数字人面试官形象 + 语音提问，贴近真实面试场景
- **知识驱动出题**：题库以知识文档形式沉淀，AI 基于检索到的知识点自主生成题目与参考答案，而非死记硬背固定题库
- **简历针对性**：解析简历后进行针对性追问，并给出人岗匹配评估
- **可量化反馈**：多维度雷达图评分 + 逐题点评 + PDF 报告导出

### 1.3 当前阶段

MVP（最小可行产品）阶段：无登录体系，先跑通核心面试闭环；数据模型按多用户设计，为后续扩展预留。

## 3. 功能需求

### 3.1 题库管理（知识文档）

**定位**：题库是"知识库"，不是"固定题库"。AI 通过 RAG 检索相关知识，自主出题、判卷、给参考答案。

| 需求项   | 说明                                             |
| ----- | ---------------------------------------------- |
| 上传    | 网页上传 Markdown（.md）文件，支持批量上传多个文档                |
| 解析与分块 | 后端解析 Markdown，按标题层级切分为语义块，向量化后存入 Chroma 向量库    |
| 知识检索  | 面试过程中，AI 根据当前岗位/难度/对话上下文，从向量库检索相关知识块，作为出题和判卷依据 |
| 题库列表  | 展示已上传的知识文档列表，支持查看、删除                           |
| 标签与岗位 | 上传时可标注所属岗位方向（前端/后端/算法…）与难度等级，作为检索过滤条件          |

**题库 Markdown 格式建议**：

```markdown
---
title: Vue 性能优化
position: 前端
difficulty: 中级
tags: [Vue, 性能优化, Webpack]
---

# Vue 性能优化

## 一、代码层面的优化

### 1.1 v-if 和 v-show 区分使用场景

v-if 是真正的条件渲染……v-show 基于 CSS display 切换……

### 1.2 computed 和 watch 区分使用场景

computed 是计算属性，有缓存……watch 用于观察监听……

## 二、Webpack 配置层面的优化
...
```

- frontmatter 的 `position` / `difficulty` / `tags` 用于检索过滤
- 标题层级（`#` / `##` / `###`）作为分块边界
- 正文为知识内容，AI 据此生成题目

### 3.2 简历管理

| 需求项  | 说明                                    |
| ---- | ------------------------------------- |
| 格式支持 | PDF、Word（.docx）                       |
| 上传   | 面试配置页上传，一份简历可复用于多次面试                  |
| 解析   | 后端提取简历文本内容（项目经历、技能、教育背景等）             |
| 轻量分析 | 上传后即时给出轻量简历分析报告：结构完整度评估、与目标岗位匹配度初评    |
| 用途   | 面试中作为 AI 针对性提问与追问的素材；终评中作为"人岗匹配"维度的输入 |
| 简历评分 | 终评中独立给出简历评分维度（区别于轻量分析：终评结合面试表现综合判断）   |

### 3.3 面试配置

用户开始一场面试前，需填写以下配置：

| 配置项   | 必选 | 说明                                       |
| ----- | -- | ---------------------------------------- |
| 岗位方向  | ✅  | 来自题库标签（前端/后端/算法/产品…），决定知识检索范围            |
| 难度    | ✅  | 初级 / 中级 / 高级，决定出题深度与追问策略                 |
| 时长    | ✅  | 15 / 30 / 45 分钟，默认 30 分钟；到时后 AI 自动收尾并出点评 |
| 面试官风格 | ⬜  | 严肃 / 温和 / 压力面，影响提问语气与追问强度（对 prompt 成本极低） |
| 简历    | ⬜  | 可选上传简历以启用针对性提问                           |

### 3.4 面试进行

#### 3.4.1 面试官形象

- **主模式（数字人）**：集成 XingyunAvatarAgent 数字人 SDK，数字人形象出题并语音播报
- **降级模式（Lottie 动画）**：当浏览器不支持 WebGL2/WebCodecs 或 SDK 加载失败时，自动降级为 Lottie/CSS 动效面试官形象 + 说话动效 + 字幕文字
- 两种模式共享同一组件接口（接收"开始说话/停止说话/播放文本"事件），业务层无感知

#### 3.4.2 提问与回答

| 需求项  | 说明                                 |
| ---- | ---------------------------------- |
| 出题来源 | 题库知识文档（RAG 检索）+ 简历内容，混合出题          |
| 提问方式 | 数字人语音播报 + 同步显示文字字幕                 |
| 回答方式 | 语音（主）：麦克风录音 → ASR 转文字；文字（兜底）：文本框输入 |
| 追问   | 每题最多 2 层追问，AI 根据回答质量决定是否追问及追问内容    |
| 时长控制 | 到达设定时长后，AI 自动收尾（不再出新题），进入点评阶段      |
| 提前结束 | 用户可随时点击"结束面试"，立即进入点评阶段             |
| 打断   | 用户可在面试官说话时打断（点击按钮或开始语音输入），进入作答     |
| 实时字幕 | 面试官提问与用户回答均以对话气泡形式实时显示             |

#### 3.4.3 面试状态机

```
[等待开始]
    ↓ 用户点击"开始面试"
[面试官提问中] ← 数字人播报题目
    ↓ 播报完成 / 用户打断
[等待用户回答] ← 语音 ASR 或文字输入
    ↓ 用户提交回答
[AI 分析中] ← LLM 评估回答 + 决定追问/换题
    ├─ 需要追问 → [面试官追问中] → [等待用户回答]（追问层级 +1，最多 2 层）
    ├─ 换题 → [面试官提问中]（下一题）
    └─ 时长到 / 无更多题 / 用户结束 → [生成点评中]
    ↓
[点评报告]
```

### 3.5 点评报告

#### 3.5.1 报告内容

| 板块    | 说明                                                   |
| ----- | ---------------------------------------------------- |
| 总评    | 整体表现概述，1–2 段文字                                       |
| 雷达图评分 | 多维度评分（0–100），维度含：专业知识、表达逻辑、人岗匹配、应变能力、技术深度            |
| 逐题点评  | 每题：题目原文、用户回答、AI 点评（亮点 + 不足 + 改进建议）、参考答案（基于检索到的知识点生成） |
| 简历评分  | 结构完整度、与目标岗位匹配度、亮点与短板                                 |
| 人岗匹配  | 结合简历与面试表现的综合匹配评估                                     |
| 总分    | 加权汇总分                                                |

#### 3.5.2 报告操作

- 查看：面试结束后即时展示
- 保存：自动保存到历史记录（按匿名用户 ID 归属）
- 导出：支持导出为 PDF 文件
- 历史：历史面试列表，可回看任意一场报告

### 3.6 LLM 配置管理

| 需求项   | 说明                                                       |
| ----- | -------------------------------------------------------- |
| 管理页入口 | 独立路由 `/admin`，需输入管理口令（环境变量配置）才能进入                        |
| 配置项   | LLM 供应商 base\_url、api\_key、model 名称                      |
| 切换    | 可保存多套配置，启用其中一套                                           |
| 默认值   | DeepSeek（`https://api.deepseek.com`），后续支持其他 OpenAI 兼容供应商 |
| 安全    | api\_key 仅存后端，前端不暴露；管理页口令校验                              |

## 4. 非功能需求

### 4.1 响应式与兼容性

| 端  | 浏览器                               | 说明                                    |
| -- | --------------------------------- | ------------------------------------- |
| 桌面 | Chrome/Edge 94+、Firefox 130+      | 完整功能                                  |
| 移动 | iOS Safari 15+、Android Chrome 94+ | 完整功能，布局自适应                            |
| 降级 | 不支持 WebGL2/WebCodecs 的浏览器         | 数字人降级为 Lottie 动画，语音降级为 Web Speech API |

响应式断点：

- 移动端：`< 768px`（单列布局，数字人区域顶部，对话区域下方）
- 平板：`768px – 1024px`
- 桌面：`> 1024px`（左右分栏：左侧数字人，右侧对话）

### 4.2 性能

- 首屏加载 ≤ 3 秒（数字人 SDK 资源可懒加载，面试配置页不阻塞）
- 面试对话响应延迟 ≤ 5 秒（含 LLM 生成 + 数字人首帧渲染）
- 简历解析 ≤ 3 秒
- 题库向量化为离线任务，上传后异步处理，不阻塞用户

### 4.3 安全

- 数字人凭证（appId/appSecret/gatewayServer）仅存后端 `.env`，前端通过后端代理获取 SDK 初始化参数
- LLM api\_key 仅存后端，前端不直连 LLM
- 管理页口令保护
- 麦克风权限需 HTTPS 或 localhost（部署时强制 HTTPS）

### 4.4 可扩展性

- LLM 供应商：OpenAI 兼容协议抽象，可一行切换
- ASR/TTS：Provider 接口抽象，可切换 SDK 默认 / 第三方 / Web Speech
- 数字人 / 降级形象：统一组件接口，可无缝切换
- 数据库：SQLModel ORM，可从 SQLite 一行配置切 PostgreSQL

## 5. 用户流程

### 5.1 首次使用流程

```
进入首页
  → 上传题库知识文档（.md）
  → 上传简历（PDF/Word）【可选】
  → 面试配置（岗位/难度/时长/风格）
  → 点击"开始面试"
  → 数字人初始化 + 首题生成
  → 面试进行（提问→回答→追问→换题 循环）
  → 时长到 / 用户结束
  → 生成点评报告
  → 查看报告 / 导出 PDF / 保存历史
```

### 5.2 历史回看流程

```
首页 → 历史记录列表 → 选择某场面试 → 查看报告详情
```

### 5.3 管理配置流程

```
访问 /admin → 输入口令 → 配置 LLM 供应商 → 保存 → 启用
```

## 6. 数据模型概要

> 详细的表结构见《技术方案》数据库设计章节。此处列出核心实体。

| 实体     | 说明             | 关键字段                                                                                            |
| ------ | -------------- | ----------------------------------------------------------------------------------------------- |
| 用户（预留） | 匿名用户，MVP 无登录   | id, anonymous\_uuid, created\_at                                                                |
| 知识文档   | 上传的题库 Markdown | id, filename, position, difficulty, tags, content, status（处理中/已就绪）                              |
| 知识块    | 文档分块向量化后的块     | id, doc\_id, chunk\_index, content, embedding\_id                                               |
| 简历     | 用户上传的简历        | id, user\_id, filename, parsed\_text, analysis\_result                                          |
| 面试记录   | 一场面试的完整记录      | id, user\_id, resume\_id, position, difficulty, duration, style, status, started\_at, ended\_at |
| 面试对话   | 逐条对话消息         | id, interview\_id, role（面试官/用户）, content, question\_index, followup\_level, created\_at         |
| 点评报告   | 面试终评           | id, interview\_id, total\_score, dimension\_scores（JSON）, summary, per\_question\_reviews（JSON） |
| LLM 配置 | 供应商配置          | id, name, base\_url, api\_key（加密）, model, is\_active                                            |
