## 1. 方案概述

AI 面试官采用 **Capacitor** 跨平台框架，将现有 Vue 3 + Web 应用打包为原生 iOS / Android 应用。

```
┌─────────────────────────────────────────────────────┐
│                一套代码，三端部署                     │
│                                                     │
│  Vue 3 + Vite + TailwindCSS                         │
│  ┌─────────────────────────────────────────────┐    │
│  │           Web 应用 (dist/)                  │    │
│  └──────┬──────────┬──────────┬────────────────┘    │
│         │          │          │                     │
│    ┌────▼────┐ ┌───▼───┐ ┌───▼─────┐               │
│    │ iOS App │ │Android│ │ 小程序  │               │
│    │(Capacitor│ │(Capacitor│ │(原生壳  │               │
│    │ WebView)│ │WebView)│ │+web-view)│               │
│    └─────────┘ └───────┘ └─────────┘               │
└─────────────────────────────────────────────────────┘
```

**核心思路**：不做任何原生开发，通过 Capacitor 自动生成包含 WebView 的原生工程，Web 代码直接在原生 App 的 WebView 中运行。

---

## 2. 核心结论：不需要原生壳

### ❌ 不需要的方案

| 方案 | 说明 |
|------|------|
| 纯原生壳（Swift/Kotlin） | 从零开发 iOS 和 Android 壳应用，维护两套原生代码 |
| React Native | 需要将 Vue 代码重写为 React，投入巨大 |
| Flutter | 需要重写全部 UI 层，无法复用现有 Web 代码 |

### ✅ 采用方案：Capacitor

**Capacitor = 一套 Web 代码 + 自动生成的原生外壳**

它为你做的事情：

1. ✅ **自动生成 Xcode 和 Android Studio 工程** — 无需手动写任何原生代码
2. ✅ **内嵌 WebView 容器** — Web 应用运行在原生 WebView 中
3. ✅ **JS Bridge** — 提供 JavaScript → 原生 API 的调用通道
4. ✅ **构建集成** — `npm run build:capacitor` 后一条命令同步到原生工程
5. ✅ **插件生态** — 摄像头、相册、文件选择、分享等原生能力开箱即用

**工作量对比**：

| 方案 | iOS 开发量 | Android 开发量 | 维护成本 |
|------|-----------|---------------|---------|
| 原生壳（Swift + Kotlin） | 2-3 周 | 2-3 周 | 双端独立维护 |
| Capacitor（本方案） | **0 天** | **0 天** | 随 Web 构建自动更新 |

## 3. 技术原理：Capacitor 是什么

### 3.1 架构原理

```
┌──────────────────────────────────────────┐
│              iOS / Android App            │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │  原生壳（Capacitor 自动生成）       │  │
│  │  - UIWebView / WKWebView           │  │
│  │  - 文件存储（NSUserDefaults 等）    │  │
│  │  - 原生插件（Camera, Share 等）     │  │
│  └────────────┬───────────────────────┘  │
│               │                          │
│        JavaScript Bridge                 │
│               │                          │
│  ┌────────────▼───────────────────────┐  │
│  │     Web 应用（dist/ 产物）          │  │
│  │     Vue 3 + TailwindCSS + 业务逻辑  │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

### 3.2 工作流程

```
1. npm run build:capacitor     # Vite 构建 Web 产物到 dist/
2. npx cap sync                # 复制 dist/ 到原生工程
3. npx cap open ios/android    # 在 Xcode/Android Studio 中打开
4. 运行 / 打包                  # 编译原生 App → .ipa / .aab
```

### 3.3 已集成的原生插件

项目 `package.json` 中已声明以下 Capacitor 插件：

| 插件 | 用途 | 使用位置 |
|------|------|----------|
| `@capacitor/camera` | 原生摄像头/麦克风 | `useMediaDevices.ts`（WebView API 不支持时降级） |
| `@capacitor/preferences` | 安全 Token 存储 | `stores/user.ts`（移动端替代 localStorage） |
| `@capacitor/share` | 原生分享面板 | `utils/bridge.ts` → `shareContent()` |
| `@capacitor/app` | App 生命周期控制 | `utils/bridge.ts` → `requestClose()` |
| `@capacitor/splash-screen` | 启动屏控制 | `capacitor.config.ts`（自动配置） |
| `@capacitor/status-bar` | 状态栏样式控制 | `capacitor.config.ts`（自动配置） |

### 3.4 环境检测逻辑

应用在运行时自动检测当前宿主环境，选择对应的 API 通路：

```typescript
// src/utils/bridge.ts
export function detectHost(): HostEnv {
  if (typeof (window as any).__wx !== 'undefined') return 'miniprogram'  // 微信小程序
  if (typeof (window as any).Capacitor !== 'undefined') return 'capacitor'  // iOS/Android App
  return 'web'  // 普通浏览器
}
```

## 4. iOS / Android 构建流程

### 4.1 前置条件

| 工具 | 要求 | 用途 |
|------|------|------|
| Node.js | 20+ | 构建 Web 产物 |
| Xcode | 15+（仅 macOS） | iOS 编译 |
| Android Studio | Hedgehog (2023.1.1) | Android 编译 |
| JDK | 17 | Android 构建 |
| CocoaPods | 最新 | iOS 依赖管理 |

### 4.2 首次初始化

> 如果项目已初始化（有 `ios/` 和 `android/` 目录），跳过此步。

```bash
# 安装所有 Capacitor 依赖（已在 package.json 中声明）
npm install

# 初始化 Capacitor（项目已配置 capacitor.config.ts）
npx cap init "AI面试官" "com.aiinterviewer.app" --web-dir=dist

# 添加 iOS 和 Android 平台
npx cap add ios
npx cap add android
```

### 4.3 配置应用标识

编辑 `capacitor.config.ts`：

```typescript
const config: CapacitorConfig = {
  appId: 'com.aiinterviewer.app',     // ← 唯一标识，上架后不可更改
  appName: 'AI面试官',                  // ← App 显示名称
  webDir: 'dist',
  server: {
    // 生产环境部署后改为：
    // url: 'https://your-domain.com',
    // cleartext: false,
  },
  // ...
}
```

### 4.4 配置 API 地址

编辑 `.env.capacitor`（生产环境）：

```env
VITE_API_BASE_URL=https://api.your-domain.com
VITE_APP_MODE=capacitor
```

开发环境使用 `npm run dev:capacitor` 会自动连接 `localhost:8000`。

### 4.5 权限配置

**iOS** — 编辑 `ios/App/App/Info.plist`：

```xml
<key>NSCameraUsageDescription</key>
<string>需要使用摄像头进行面试录制</string>
<key>NSMicrophoneUsageDescription</key>
<string>需要使用麦克风进行面试录音</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>需要选择图片作为简历或头像</string>
```

**Android** — 编辑 `android/app/src/main/AndroidManifest.xml`：

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

### 4.6 构建与同步

```bash
# 构建 Web 产物（capacitor 模式）
npm run build:capacitor

# 同步到原生工程
npm run cap:sync
# 等价于: npx cap sync
# 会自动:
#   1. 复制 dist/ 到 ios/App/public/ 和 android/app/src/main/assets/public/
#   2. 安装 Pod 依赖
#   3. 复制 Capacitor 插件到原生工程
```

### 4.7 生成签名证书

#### Android 签名

```bash
# 生成签名密钥（仅需一次，妥善保管）
keytool -genkey -v -keystore release.keystore \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias ai-interviewer

# 在 android/app/build.gradle 中配置签名
# android {
#   signingConfigs {
#     release {
#       storeFile file('../release.keystore')
#       storePassword 'your_password'
#       keyAlias 'ai-interviewer'
#       keyPassword 'your_password'
#     }
#   }
#   buildTypes {
#     release {
#       signingConfig signingConfigs.release
#     }
#   }
# }
```

#### iOS 签名

在 Xcode 中配置：
1. 登录 Apple Developer 账号
2. 选择 Team
3. 设置 Bundle Identifier（与 `appId` 一致）
4. 选择自动签名或手动配置 Provisioning Profile

### 4.8 打包发布

#### 生成 APK / AAB（Android）

```bash
# 在 Android Studio 中:
# Build → Generate Signed Bundle / APK
# 选择 "Android App Bundle (AAB)"
# 选择 release 签名配置
# 输出: android/app/build/outputs/aar/release/

# 或命令行:
cd android
./gradlew assembleRelease
# 输出: android/app/build/outputs/apk/release/app-release.apk
```

#### 生成 IPA（iOS）

```bash
# 在 Xcode 中:
# Product → Archive
# 归档完成后: Organizer → Distribute App → App Store Connect

# 或命令行:
cd ios
xcodebuild -workspace App/App.xcworkspace \
  -scheme App \
  -configuration Release \
  -destination 'generic/platform=iOS' \
  -archivePath ./build/App.xcarchive \
  archive
```

## 6. 发布上架

### 6.1 Android — Google Play / 国内应用商店

1. 生成 `AAB` 签名包（见 4.8 节）
2. 注册 [Google Play Console](https://play.google.com/console) 开发者账号（$25 一次性）
3. 上传 AAB → 填写应用信息 → 提交审核
4. 国内应用商店：华为、小米、OPPO、vivo、应用宝等（需分别注册）

### 6.2 iOS — App Store Connect

1. 注册 [Apple Developer](https://developer.apple.com) 账号（$99/年）
2. 在 App Store Connect 创建 App 条目
3. Archive 上传 IPA（通过 Xcode Organizer 或 `xcodebuild`）
4. 填写 App Store 信息 → 提交审核 → 等待审核（通常 24-48 小时）

### 6.3 审核注意事项

| 注意点 | 说明 |
|--------|------|
| 隐私说明 | 需提供隐私政策 URL，声明数据收集用途 |
| 摄像头权限 | 需在 Info.plist 中详细说明用途（已配置） |
| 麦克风权限 | 同上 |
| 网络权限 | App Transport Security 要求 HTTPS（开发模式 `cleartext: true` 仅用于调试） |
| 退出 App | iOS 不允许 `App.exitApp()`，代码中已做平台判断 |
| 数字人内容 | AI 生成内容需符合平台内容政策，建议增加用户举报/反馈入口 |

### 6.4 更新发布流程

```bash
# 1. 修改版本号 (package.json)
# 2. 构建新版本
npm run build:capacitor
npx cap sync

# 3. 生成新签名包
#    Android: ./gradlew assembleRelease
#    iOS: Xcode → Archive

# 4. 上传到应用商店
#    Google Play: 上传新 AAB（版本号递增）
#    App Store Connect: 上传新构建（build number 递增）
```

## 7. 原生能力桥接

### 7.1 当前已实现

| 能力 | Web 端 | Capacitor (iOS/Android) | 实现位置 |
|------|--------|------------------------|----------|
| 摄像头 | `getUserMedia` 直接调用 | 优先 `getUserMedia`，不支持时降级 `@capacitor/camera` | `useMediaDevices.ts` |
| 麦克风 | `getUserMedia` 直接调用 | 同上 | `useMediaDevices.ts` |
| 文件选择 | `<input type="file">` | `@capacitor/file-picker` | `useMobile.ts` |
| 分享 | `navigator.share` | `@capacitor/share` | `bridge.ts` → `shareContent()` |
| Token 存储 | `localStorage` | `@capacitor/preferences` | `stores/user.ts` |
| 关闭页面 | `window.history.back()` | iOS: `SwipeBack` / Android: `App.exitApp()` | `bridge.ts` → `requestClose()` |

### 7.2 扩展新的原生能力

如需接入新的原生能力（如推送通知、生物识别等）：

```bash
# 1. 安装 Capacitor 插件
npm install @capacitor/push-notifications

# 2. 创建桥接封装
# src/utils/push.ts
export async function registerPush(): Promise<string | null> {
  const host = detectHost()
  if (host !== 'capacitor') return null
  try {
    const { PushNotifications } = await import('@capacitor/push-notifications')
    await PushNotifications.register()
    return 'registered'
  } catch {
    return null
  }
}

# 3. 在应用初始化时调用
# src/App.vue 或 main.ts 中
```

### 7.3 降级策略

```
用户操作 → detectHost() 判断环境
  │
  ├── capacitor（App）
  │   ├── 优先：原生插件 API
  │   └── 降级：Web API（如果可用）
  │
  ├── miniprogram（小程序）
  │   ├── 通过 bridge.js → 宿主 JSAPI
  │   └── 降级：纯 Web API
  │
  └── web（浏览器）
      └── 标准 Web API
```

## 8. 微信小程序集成

### 8.1 架构

```
┌─────────────────────────────────────┐
│         微信小程序（原生壳）          │
│  ┌────────────────────────────────┐  │
│  │  <web-view src="H5 URL">       │  │
│  │    ↓                           │  │
│  │  H5 页面 = 已部署的 Web 应用    │  │
│  │  （与 Web 端同一份 dist/ 产物） │  │
│  └────────────────────────────────┘  │
│                                     │
│  bridge.js ← JSSI 通信 → H5         │
└─────────────────────────────────────┘
```

### 8.2 小程序壳位置

`miniprogram/` 目录包含完整的微信小程序壳工程：

```
miniprogram/
├── app.js                  # 入口（读取 webViewUrl）
├── app.json                # 全局配置
├── app.wxss                # 全局样式
├── project.config.json     # 项目配置（AppID 等）
├── sitemap.json
├── pages/index/
│   ├── index.wxml          # <web-view> 组件
│   ├── index.js            # 页面逻辑 + JSSI 处理
│   ├── index.json          # 页面配置
│   └── index.wxss
└── utils/bridge.js         # JSSI 通信封装
```

### 8.3 配置步骤

1. 用微信开发者工具打开 `miniprogram/` 目录
2. 在 `project.config.json` 中设置 AppID
3. 修改 `app.js` 中的 `webViewUrl` 为已部署的 HTTPS 地址
4. 在微信公众平台配置域名白名单：
   - 业务域名（H5 页面域名）
   - request 合法域名（API 域名）
5. 在微信开发者工具中上传 → 提交审核 → 发布

### 8.4 H5 与小程序通信

| 方向 | 方式 | 场景 |
|------|------|------|
| 小程序 → H5 | `evalJS` → `window.__onMiniMessage` | 分享回调、登录状态通知（实时） |
| H5 → 小程序 | `wx.miniProgram.navigateBack` | 关闭页面、返回上一页 |
| H5 → 小程序 | URL hash `#/mp-action?action=xxx` | 触发小程序原生能力 |
| H5 → 小程序 | `postMessage` | 延迟消息（导航/分享时传递） |

通信桥接已在 `src/utils/bridge.ts` 中实现，Web 端代码无需修改。

### 8.5 小程序特殊限制

| 限制 | 说明 | 应对 |
|------|------|------|
| 不支持 WebGL | 小程序 `<web-view>` 中 WebGL 可能不可用 | `useAvatar.ts` 中自动降级为 Lottie 动画 |
| 无法直接访问 DOM | 小程序页面和 web-view 内容隔离 | 通过 JSSI 通信桥接 |
| 域名必须 HTTPS | 微信强制要求 | 部署到 HTTPS 服务器 |
| 不支持 `navigator.share` | 小程序 web-view 限制 | 使用 `wx.showShareMenu` |

## 9. 常见问题

### Q1：Capacitor 和原生开发有什么区别？

Capacitor 让你**不需要写任何原生代码**。它在编译时自动将 Web 产物嵌入一个原生 WebView 容器，并提供 JS Bridge 调用原生 API。最终生成的 App 是真正的原生 App（不是 PWA），可上架 App Store 和 Google Play。

### Q2：为什么不直接用 PWA？

| 对比项 | Capacitor App | PWA |
|--------|---------------|-----|
| App Store 上架 | ✅ 可上架 | ❌ 不可上架 |
| 原生体验 | ✅ 启动屏、状态栏等原生体验 | ❌ 浏览器壳 |
| 原生 API | ✅ 完整 Bridge 访问 | ❌ 受限 |
| 离线能力 | ✅ 原生文件系统 | ❌ Service Worker 限制 |
| 推送通知 | ✅ 原生推送 | ❌ Web Push 限制多 |

### Q3：开发时 App 连不上 localhost？

```bash
# 确认 capacitor.config.ts 中 server 配置
server: {
  url: 'http://localhost:5173',
  cleartext: true,  # 允许 HTTP（非 HTTPS）
}

# Android: adb reverse 映射端口
adb reverse tcp:5173 tcp:5173
adb reverse tcp:8000 tcp:8000

# iOS: 确保手机和电脑在同一局域网
# 或使用 USB 调试模式
```

### Q4：生产环境 App 如何加载 H5？

生产环境有两种模式：

```typescript
// 模式 A：App 内嵌所有 Web 资源（离线可用）
// capacitor.config.ts 中不配置 server.url
// npx cap sync 时 Web 产物被打包进 App
// → 完全离线运行，API 调用远程后端

// 模式 B：App 加载远程 H5（动态更新）
// capacitor.config.ts 中配置
server: {
  url: 'https://your-domain.com',
  cleartext: false,
}
// → App 是一个 WebView 壳，加载线上 H5 页面
// → 好处：H5 更新无需重新提交 App Store
```

**推荐**：模式 A（内嵌资源），配合 App Store 的版本更新。如果需要频繁更新 H5，可使用模式 B，但需考虑 App Store 审核政策。

### Q5：如何处理 App 版本更新？

- **H5 改动**：如果是模式 B，直接更新服务器上的 H5 即可。如果是模式 A，需要重新构建并提交审核。
- **原生插件改动**：必须重新构建，提交审核。
- **强制更新**：后端返回 `min_version` 字段，App 启动时检查并提示更新。

### Q6：数字人在移动端表现如何？

| 平台 | WebGL | 降级策略 |
|------|-------|----------|
| Android（高端机） | ✅ 可用 | 使用 WebGL 3D 数字人 |
| Android（低端机） | ❌ 不可用 | 降级为 Lottie 动画 + TTS 音频 |
| iOS（全部） | ⚠️ 部分支持 | 自动检测，降级为 Lottie |

降级逻辑已在 `src/composables/useAvatar.ts` 中实现。

### 10.3 总结

**AI 面试官选择 "Capacitor + 原生小程序壳" 方案的核心理由**：

1. **最大化代码复用** — 95%+ 的 Web 代码可直接在移动端运行，包括业务逻辑、UI 组件、状态管理
2. **零原生开发** — 不需要写一行 Swift / Kotlin 代码，降低技术门槛
3. **统一技术栈** — 团队只需掌握 Vue/TypeScript，无需额外学习
4. **快速迭代** — Web 端修改后，移动端构建只需 `npm run build:capacitor && npx cap sync`
5. **跨平台覆盖** — 一套方案覆盖 iOS、Android、微信小程序三大移动端
6. **维护简单** — 没有多端代码分叉，功能同步只需改一处
